# Design KPI и критерии качества для MVP

## 1) Ключевые метрики продукта и UX

| Метрика | Что измеряем | Целевое значение для MVP | Как фиксируем факт |
|---|---|---|---|
| **TTI / LCP** | Скорость готовности интерфейса к взаимодействию и крупнейшего контентного блока | LCP ≤ 2.5s (p75), TTI ≤ 3.5s на целевых устройствах | Lighthouse/Web Vitals отчёты по каждому релизу |
| **Task success rate** | Доля пользователей, завершивших целевой сценарий без помощи | ≥ 80% в ключевом флоу | Юзабилити-тесты (5–10 респондентов) + продуктовая аналитика |
| **Time-to-action** | Время от открытия главного экрана до первого целевого действия (CTA) | ≤ 10s для нового пользователя | Event-таймстемпы в аналитике |
| **Error rate** | Доля сессий/действий с ошибками UX или техническими сбоями | ≤ 2% в ключевых сценариях | Логи фронтенда, аналитика ошибок, QA-репорты |

---

## 2) Критерии для главного экрана

### 2.1 Понятность ценности за 5 секунд
- Пользователь за первые 5 секунд отвечает:
  - что это за продукт;
  - какую проблему он решает;
  - зачем нажимать основную кнопку.
- Проходной критерий: не менее **4 из 5** участников экспресс-теста формулируют ценность корректно.

### 2.2 CTA visibility
- Основной CTA виден **без скролла** на популярных мобильных и desktop-разрешениях.
- Визуальная иерархия направляет к CTA (контраст, размер, отступы, позиция).
- Проходной критерий: не менее **90%** сессий с первым кликом по одному из целевых CTA.

### 2.3 Контраст AA
- Текст и интерактивные элементы соответствуют **WCAG 2.1 AA**:
  - обычный текст: минимум 4.5:1;
  - крупный текст: минимум 3:1;
  - элементы управления и границы: минимум 3:1.
- Проходной критерий: 0 критичных замечаний по контрасту в автоматической проверке + ручной spot-check.

## 3) Критерии для PWA

### 3.1 Offline recovery
- Приложение корректно обрабатывает потерю сети:
  - отображает понятный офлайн-стейт;
  - сохраняет пользовательское действие в очередь (если применимо);
  - автоматически восстанавливает выполнение после возвращения сети.
- Проходной критерий: ключевой сценарий не теряется при offline/online переключении в тесте.

### 3.2 Navigation clarity
- Пользователь понимает, где находится, как вернуться и какой следующий шаг.
- Навигационные элементы консистентны между экранами.
- Проходной критерий: не менее **80%** пользователей проходят многошаговый сценарий без подсказок.

### 3.3 Touch accuracy
- Интерактивные зоны на touch-устройствах не меньше 44×44 px.
- Нет систематических промахов по целевым элементам.
- Проходной критерий: доля mis-tap по ключевым действиям ≤ 5%.

## 4) Привязка критериев к этапам MVP

| Этап MVP | Что проверяем | Факт прогресса |
|---|---|---|
| **MVP-0: Baseline (до пилота)** | TTI/LCP, контраст AA, базовая видимость CTA | Есть первичный бенчмарк и устранены блокирующие UX/доступность-проблемы |
| **MVP-1: First usable flow** | Task success rate, time-to-action, понятность ценности за 5 секунд | Не менее 80% успеха в ключевом сценарии и time-to-action в целевом коридоре |
| **MVP-2: PWA readiness** | Offline recovery, navigation clarity, touch accuracy | PWA-сценарии проходят QA и пользовательский smoke-тест без критичных сбоев |
| **MVP-3: Stabilization** | Error rate + все критерии в динамике | Метрики держатся в целевых диапазонах минимум 2 релизных цикла подряд |

### Формат отчётности по фактам
Для каждого этапа фиксируем:
1. Дату замера и версию релиза.
2. Фактические значения метрик.
3. Статус критерия: ✅ выполнено / ⚠️ частично / ❌ не выполнено.
4. Список решений и следующих корректирующих действий.
