# Design KPI и quality-gates для UI/Frontend

## 1) KPI-метрики для дизайна и UX

### CTA visibility
- **Что измеряем:** долю пользователей, увидевших ключевой CTA на первом экране без скролла.
- **Целевой ориентир:** не ниже **90%** на основных пользовательских сценариях.
- **Проверка:** аналитика viewport + heatmap/session replay + ручной QA на целевых разрешениях.

### Task success rate
- **Что измеряем:** процент пользователей, завершивших целевой сценарий (например, создание сущности, оформление действия) без помощи поддержки.
- **Целевой ориентир:** не ниже **85%** для новых сценариев после стабилизации.
- **Проверка:** funnel-анализ по шагам + UX-тесты на 5–10 респондентах.

### Time-to-first-action
- **Что измеряем:** время от открытия экрана до первого осмысленного действия пользователя.
- **Целевой ориентир:** медиана не более **8 секунд** для основных экранов.
- **Проверка:** продуктовая аналитика событий `screen_open -> first_action`.

### Error recovery
- **Что измеряем:** долю пользователей, успешно восстановившихся после ошибки (валидация, сеть, бизнес-ошибка) и завершивших задачу.
- **Целевой ориентир:** не ниже **70%**.
- **Проверка:** события `error_shown -> retry/success`, анализ текстов ошибок и CTA восстановления.

## 2) PWA-критерии для мобильного сценария

### Offline-state
- Должен быть явный экран/баннер состояния offline.
- Пользователь получает понятное действие восстановления (retry, autosync при reconnect).
- Критически важные read-only данные по возможности доступны из кэша.

### Skeleton loading
- Для всех ключевых мобильных экранов используется skeleton вместо «прыгающего» контента.
- Структура skeleton повторяет финальный layout, чтобы минимизировать CLS и когнитивную нагрузку.

### Touch-target size
- Интерактивные элементы (кнопки, иконки, пункты списка) имеют touch-target не менее **44x44 px**.
- Между соседними интерактивными зонами соблюдается безопасный отступ.

## 3) Дизайн-чеклист в PR-процесс

Каждый PR с изменениями UI/UX обязан содержать чеклист:

- [ ] **Консистентность токенов:** цвета, типографика, spacing, radius, shadows берутся из дизайн-токенов.
- [ ] **Доступность (a11y):** контраст, фокус-состояния, keyboard navigation, корректные aria-атрибуты.
- [ ] **Motion-лимиты:** анимации не мешают задачам, соблюдены ограничения по длительности/частоте, учитывается `prefers-reduced-motion`.

---

## 4) Definition of Done для frontend-фич

Frontend-фича считается завершённой, если выполнены все пункты:

- [ ] Реализованы **все экранные состояния**: loading, empty, error, partial/success.
- [ ] Пройдены базовые **a11y-проверки**: семантика, фокус, контраст, screen-reader labels.
- [ ] Подтверждена **responsive-адаптация** на целевых брейкпоинтах.
- [ ] Выполнена **API integration**: обработка success/error/timeout/retry, корректные состояния UI.
- [ ] Добавлены необходимые продуктовые события аналитики для KPI.

## 5) Единый шаблон ревью для всех UI PR

Использовать следующий унифицированный шаблон в описании/ревью UI PR:

```md
## UI Review Template

### Scope
- Что изменено в интерфейсе:
- Какие пользовательские сценарии затронуты:

### Design Consistency
- [ ] Использованы дизайн-токены (color/type/spacing/radius)
- [ ] Нет локальных style override без обоснования

### Accessibility
- [ ] Контраст соответствует требованиям
- [ ] Полная keyboard-навигация
- [ ] Корректные aria-label/roles
- [ ] Видимый focus state

### Motion & Interaction
- [ ] Анимации соответствуют motion-лимитам
- [ ] Учтён prefers-reduced-motion
- [ ] Touch-target >= 44x44 px (mobile)

### States & Responsiveness
- [ ] Реализованы loading/empty/error/success состояния
- [ ] Проверены мобильный/планшет/десктопный брейкпоинты
- [ ] Offline-state и skeleton loading для PWA-сценариев

### API & Error Handling
- [ ] Корректная обработка success/error/timeout
- [ ] Есть понятные сообщения об ошибках и шаги восстановления

### KPI Impact
- [ ] Привязка к KPI: CTA visibility / task success rate / time-to-first-action / error recovery
- [ ] Добавлены/обновлены аналитические события

### Evidence
- Ссылка на макет(ы):
- Скриншоты/видео до-после:
- Чек результатов тестирования:
```

Рекомендуется сделать этот шаблон обязательным в PR-процессе для всех изменений UI.
