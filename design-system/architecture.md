# Naming и composability правила

## 1) Префиксы и структура
- Блоки компонентов имеют префикс `ui-` (`ui-control`, `ui-card`, `ui-modal`).
- Модификаторы состояния описываются через `is-*` (`is-hover`, `is-loading`, `is-error`).
- Лэйаут/утилиты отделены префиксом `u-` (`u-row`, `u-stack`) и не содержат визуальной логики компонентов.

## 2) Токены как единственный источник дизайна
- Любые цвета, отступы, радиусы, тени, motion и z-index берутся только из `tokens.css`.
- Компоненты не хардкодят значения для этих категорий.
- Светлая/темная тема реализуются заменой значений токенов через `[data-theme="dark"]`.

## 3) Композиция вместо дублирования
- Базовый слой: общие стили (`.ui-control`, `.ui-input`, `.ui-card`).
- Варианты: добавочные классы (`.ui-control--primary`, `.ui-tab.is-active`).
- Состояния: одинаковый словарь для всех компонентов: `default`, `hover`, `focus`, `disabled`, `loading`, `error`, `success`.

## 4) Масштабирование
- Новый компонент начинается с базового блока `ui-*`, затем подключает общие токены и общие state-классы.
- Визуальные изменения вносятся через токены, чтобы весь UI менялся централизованно.
- Каталог (`catalog.html`) — живой контракт по визуальным состояниям для команды.
